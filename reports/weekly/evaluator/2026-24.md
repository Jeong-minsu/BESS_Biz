## Cross-Agent Patterns — New This Week

**Pattern 13: Execution Divergence Is Structural, Not Episodic**

Observed across all three PRODUCTION bess-optimizer comparison days in W24 (2026-06-10, 2026-06-12, 2026-06-14): Smartbidder/Tenaska consistently executed a different strategy than bess-optimizer recommended — and consistently outperformed the recommendation. The evaluator cannot currently determine whether bess-optimizer and dart-virtual-trader are advisory agents or execution-controlling agents. This is a fundamental architectural ambiguity that affects how both agents should be scored on Approach.

**Pattern 14: ECRS DA Clearing Is a Recurring Tail Event That Agents Cannot Pre-Predict**

Observed on 2026-06-08, 2026-06-12, 2026-06-13, 2026-06-14: ECRS cleared unexpectedly on 4 of 7 W24 days. The bess-optimizer excluded ECRS each time (citing "zero clearing in 4+ consecutive days") and the market-analyst did not provide ECRS price forecasts because Smartbidder AS endpoints either failed or did not include ECRS. Simultaneously, dart-virtual-trader's 2026-06-14 loss was caused by an ECRS-driven RT scarcity event that the model did not account for. The pattern suggests ECRS clearing in the evening hours is now a structural feature of the June 2026 ERCOT market (heat season, high loads, 10-12 GW outage stack), not a rare tail event. All agents should treat ECRS as a standing signal in June-September ERCOT conditions.

**Pattern 15: Agent Learning Loop Speed Varies Systematically by Change Type**

Observed across W21-W24 for all agents: rule changes that affect a single per-cycle decision (e.g., charge window timing, congestion-analyst P90 multiplier, dart-virtual-trader position sizing) are implemented within 1-2 cycles. Template-level changes that require a persistent document or code modification (ECRS standing offer, weekend RT override step, hit-rate-log creation, Submissions-DA-Settlement-Amounts endpoint) are deferred indefinitely. The distinction is: per-cycle decisions can be implemented by changing what the agent does in one step; structural changes require creating something that persists across cycles. No agent has a mechanism for tracking unimplemented structural changes — the closest is the evaluator's improvement-tracker.md, but agents do not consult it before generating their daily output.
