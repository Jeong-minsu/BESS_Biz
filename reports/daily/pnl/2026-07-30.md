### [P1 — 긴급] Tenaska endpoint cache 설정 (`.env` 환경 변수 추가)

**원인**: 클라우드 자동화 환경은 비대화형(non-interactive)이므로 Tenaska PTP endpoint 동적 discovery 불가. `TENASKA_EP_*` env var가 없으면 discovery loop에서 stdin 입력을 기다리다 차단됨.

**조치 — 1회 수동 discovery 후 캐시 고정**:

**Step 1**: Ascend-whitelisted IP 환경 (로컬 PC 또는 VPN)에서 `fetch_pnl_data.py`를 interactive 모드로 실행:
```bash
python shared/scripts/fetch_pnl_data.py --flowday 2026-07-30
```
실행 중 화면에 endpoint URL 4종이 출력되거나 선택을 요구함 (프롬프트 형식은 fetch script 구현에 따라 다름). URL 4종을 복사.

**Step 2**: `.env` 파일 `[Tenaska]` 섹션에 아래 4개 변수 추가:
```
# [Tenaska] 섹션 — endpoint cache (비대화형 실행을 위해 고정)
TENASKA_EP_ENERGY_AS=<Energy and AS Details endpoint URL>
TENASKA_EP_DA_BID=<DA Energy Bid Market Result endpoint URL>
TENASKA_EP_DA_OFFER=<DA Energy Only Offer Market Result endpoint URL>
TENASKA_EP_HSL=<HSL (High Sustained Limit) endpoint URL>
```

**Step 3**: 설정 후 클라우드 환경에서 재실행:
```bash
python shared/scripts/fetch_pnl_data.py --flowday 2026-07-30
```
→ stdin 입력 없이 endpoint cache를 읽어 실행되어야 함.

> **주의**: endpoint URL은 Tenaska PTP 내 GKS 리소스에 해당하는 특정 URL이어야 함. `.env`에 기록 후 git commit 금지 (`.env`는 `.gitignore` 대상).
