## 2. Smartbidder 데이터 없을 때의 한계

### 분석 품질 영향 (심각도 High)

| 항목 | 정상 상태 | 오늘 상태 | 영향 |
|---|---|---|---|
| DA 가격 예측 ($X/MWh) | Smartbidder 수치 | 없음 | 입찰 가격 기준 수치 제시 불가 |
| RT 스파이크 확률 | P(RT>$100) per HE | 없음 | 리스크 정량화 불가 |
| P(DA>RT) / DA-RT 스프레드 | 확률값 + 방향 | 없음 | DART 포지션 근거 없음 |
| AS 예측 (RRS/ECRS/Non-spin) | $/MWh per product | 없음 | AS 스택 최적화 불가 |
| DA vs RT 비교 | 숫자 비교 | 없음 | 아비트라지 기회 식별 불가 |

### bess-optimizer / dart-virtual-trader에 대한 영향
- bess-optimizer는 가격 예측 없이 net-load curve만으로 "충전 HE10-11, 방전 HE19-20" 방향성 추론 가능
- 단, 수익 추정($) 불가 → 정성적 포지션 권고만 가능
- dart-virtual-trader는 P(DA>RT) 없이 사실상 의사결정 불가 — 운용 중단 권고

### 단일 데이터 소스 의존 리스크

- 특히 load forecast: 기상 모델이 당일 수정될 경우 bidclose vintage가 구식이 될 수 있음

## 4. 개선 포인트

### 즉시 조치 필요
1. **Smartbidder client_secret 갱신**: Ascend rep에 갱신 요청 — 가격 예측 / AS spread / P(DA>RT) 없이 브리핑 품질이 전략적으로 반쪽. 최우선 과제.
2. **AG2 WSI 독립 호출 구현**: Smartbidder와 별개 credential로 AG2 직접 호출 경로 확인. `fetch_market_data.py` 의존성 분리 여부 검토.

### 분석 방법론 개선
3. **HE24 Cap Out 이상치 처리 규칙 필요**: 전날 대비 급변 시 자동 flag + congestion-analyst에 확인 요청하는 표준 절차 수립.
4. **Net-load ramp 계산 자동화**: HE-by-HE ramp 크기를 수동 계산하는 현재 방식 대신, Python 스크립트로 ramp 지표(2h rolling delta, max ramp window) 자동 추출.
5. **단일 소스 경보 체계**: Yes Energy 외 소스 모두 없을 때 브리핑 앞부분에 "DATA QUALITY WARNING" 블록을 더 눈에 띄게 강조. 현재는 DATA SOURCE STATUS 표만 있음.

### 브리핑 형식 개선
6. **Off-peak 섹션**: Negative price 가능 HE 식별을 "HE10-11 negative 가능" 수준으로 더 명확히 표현. 현재 "가능성 있음" 수준에 그침.
7. **BESS dispatch 시사점 명시**: bess-optimizer를 위한 "충전 창/방전 창 우선순위" 표를 브리핑 내 별도 섹션으로 추가하면 downstream 에이전트가 쉽게 참조 가능.
